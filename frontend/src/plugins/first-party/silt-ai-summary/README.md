# silt-ai-summary

A dismissible highlight at the top of each note with a 2–3 sentence summary
plus any new **tasks**, **risks**, and **decisions** the note contains —
generated by your configured LLM.

This is Silt's first AI-capable first-party plugin. It builds on the Sprint 19
`note-banner` surface and the Sprint 20 AI service (a local or
OpenAI-compatible chat model). Summaries are cached by content hash in the
plugin's own SQLite store and re-derived only when the note or the chat model
changes; "new" items are diffed against the prior snapshot so edits stand out.

**Off by default.** It is the first plugin that sends note content to an
external LLM endpoint, so you opt in explicitly after configuring a provider.

## What it does

When you open a note (and after a debounced save), the plugin asks your chat
model to return a structured extraction:

```json
{
  "summary": "2–3 sentences on what the note is about",
  "tasks": ["...actionable to-dos..."],
  "risks": ["...concerns/blockers..."],
  "decisions": ["...decisions made..."]
}
```

The result renders as a banner pinned above the editor. Items that are new
since the last generation are badged **New**. The banner is dismissible per
note; a status-bar chip lets you re-show it.

## Enable

1. Open **Settings → Plugins** and enable **AI Summary**.
2. Open **Settings → AI Summary** to tune what it shows (facets, length, timing).

It needs an AI provider configured (see below) before it generates anything.
Without one, the banner shows a one-line "configure a provider" nudge and
makes **no network calls** until you do.

## Configure the model

Summaries run against your **chat** provider (the embedding provider is not
used). See [`docs/BRING_YOUR_OWN_MODEL.md`](../../../../docs/BRING_YOUR_OWN_MODEL.md)
for local (Ollama, LM Studio, llama.cpp) and cloud (OpenAI-compatible:
OpenRouter, OpenAI, Together, …) setup. Local providers run keyless; cloud
providers need an API key.

Recommended local models for structured extraction at this scale: Qwen3-30B-A3B,
Gemma 4 26B-A4B. Weaker models still work — the extractor has a three-tier
fallback (parse → retry → summary-only) so you always get at least a summary.

## Tune it

**Settings → AI Summary** exposes:

- **When to generate** — automatically on note open, or only when you click
  Regenerate (on-demand).
- **Summary length** — short / medium / long.
- **Facets to show** — toggle tasks / risks / decisions.
- **Regenerate debounce** — how long after a save to wait before regenerating.
- **Max note size** — notes larger than this are skipped (chunking is a future
  enhancement; lower it to cap compute on long notes).

## Dismiss & regenerate

- **Close (×)** dismisses the banner for the current note's content. Dismissal
  is keyed by `pageId:contentHash`, so **editing the note re-shows the banner**
  on the next open (the content hash changes). A **Show AI summary** chip
  appears in the status bar to re-open it manually at any time.
- **Regenerate (↻)** forces a fresh extraction for the current note, bypassing
  the cache.
- Unconfigured and oversized states include a **settings deep-link** CTA that
  jumps straight to Settings → AI (or this plugin's settings tab).

## Privacy

Note content (the cleaned text of the note's blocks) is sent to **your
configured AI endpoint** to produce the summary. Nothing else leaves your
device. Every call is audit-logged — open
**Settings → AI → Recent AI activity** to see the call log (plugin,
model, status, token counts). Message content and embedding vectors are never
recorded.

## Caching

Summaries are cached in the plugin's own SQLite store
(`<vault>/.system/plugins/silt-ai-summary/data/plugin.db`), keyed by page id +
a sha256 of the note's clean content. A note is re-summarized only when its
content changes or when you switch chat models (the model id is stored with
each row, so a model change invalidates the cache). **The cache is safe to
clear** — delete the file and summaries rebuild on the next open.

This is plugin-owned storage, not the core index: per Silt's storage-of-truth
contract (ARCHITECTURE.md §0 rule 4 plugin carve-out), it is disposable working
memory and never the source of truth for your notes (markdown is).

## Troubleshooting

- **Reasoning tags in the summary?** Models that "think" (DeepSeek-R1, Qwen3
  thinking, …) wrap internal reasoning in `<thought>`/`<think>` tags. Silt strips
  these before the summary is rendered or cached, so you should only ever see
  clean prose. If tags still appear, the summary predates the fix — click
  **Regenerate** to refresh it.
- **"Configure an AI provider" nudge won't go away** — set a chat model in
  Settings → AI. Local providers (Ollama) need no key; cloud providers
  need an API key.
- **Empty summary / "Nothing to highlight"** — the note has no extractable
  content, or the model returned nothing usable. Try Regenerate, or a stronger
  model.
- **Slow generation** — large notes + a small local model can take 10–60s.
  Lower **Max note size** or use a faster model. Generation runs off the UI
  thread; the editor stays responsive.
- **Stale banner after switching models** — switch the chat model in
  Settings → AI and click Regenerate; the cache invalidates on model
  change automatically.

## For developers

This plugin is the reference consumer of three Sprint 19/20 mechanisms:

- the **first-party `note-banner` surface** (a compiled Svelte component mounted
  by `PluginNoteBanners`, see `surfaces.ts` `component?` field),
- the **bespoke plugin settings page** (`AISummarySettings.svelte` via the
  registry's `settingsPageComponent`),
- the **`ai` capability** (`ctx.ai.complete`) + **`plugin-db`** cache.

See [`docs/PLUGIN_DEVELOPMENT.md`](../../../../docs/PLUGIN_DEVELOPMENT.md) §8.13
(note-banner), §8.12 (bespoke settings), and §8.14 (AI) for the author guide.
