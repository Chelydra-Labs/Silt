## Exact release and compatibility evidence

- The [official Go release history](https://go.dev/doc/devel/release) lists Go 1.26.10 (released 2026-10-19) and says it includes `crypto/x509` security fixes. It also lists Go 1.27.3 (released 2026-10-19) with `crypto/x509` security fixes. The [official Wails v3.0.0 release](https://github.com/wailsapp/wails/releases/tag/v3.0.0), published 2026-10-26, supports Go 1.26+ and recommends 1.26.10 or 1.27.3 for the `crypto/x509` fix. This PR's Go 1.26.10 and Wails v3.0.0 pins therefore satisfy Wails' stated minimum/recommendation. Go 1.27.3 is newer; this review does not infer it is a drop-in replacement for the approved coordinated pins.
- The official [Wails v3.0.0 release notes](https://github.com/wailsapp/wails/releases/tag/v3.0.0) establish exact matching Go module, CLI, and `@wailsio/runtime` release `v3.0.0`/`3.0.0`, and state Linux defaults to GTK4 while GTK3 remains available using `-tags gtk3` until v3.1. That is the source for the ADR's planned v3.1 removal timeline.
- The release notes characterize v3.0.0 as a ground-up major-version release and document migration guide availability. Issue [#982](https://github.com/Chelydra-Labs/Silt/issues/982) records inspected beta.31 security-relevant additions absent from beta.9 and the coordinated Go/runtime/toolchain requirements. The PR's code changes and prior checks cover application/API adaptation; this review does not claim that those checks prove absence of every upstream behavior change.

## Advisory and scanner evidence

- Go's official [Go vulnerability database entry GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809) is the `crypto/x509` issue called out by both release sources. Go 1.26.10's official release history says the release includes `crypto/x509` security fixes. Issue [#979](https://github.com/Chelydra-Labs/Silt/issues/979) lists the prior reachable standard-library findings and reports they were fixed in Go 1.26.9; the 1.26.10 release then adds the later x509 fix.
- Wails v3.0.0's release notes say all published Wails v3 advisories are fixed except [GHSA-2p5f-2gx8-mh8m](https://github.com/advisories/GHSA-2p5f-2gx8-mh8m), which is only partially fixed: cross-origin child frames are blocked on Linux, while same-origin child-frame limitations remain. The release notes explicitly warn against embedding untrusted same-origin content. This is a documented upstream limitation, not a clean-advisory claim.

They do not establish the complete current Silt dependency graph's advisory status. That remains the role of `govulncheck`, npm audit, and the hosted dependency/security scan.
